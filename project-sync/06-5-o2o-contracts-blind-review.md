# O2O Step 7 산출물 블라인드 검증 기록 (06-4 v3 대상)

수행: 2026-09-04. /ddd-blind-review 감사 모드
대상: 06-4-o2o-contracts.md v3, 06-4-o2o-contracts-explained.md v3
방식: 격리 폴더에 대상 2 + 상위 입력 3(애그리거트, 정책 초안, 용어 사전) + 입력 팩(쟁점과 권고 제거판)만 복사. 계획서(01)와 대화 이력 미전달. 읽기 전용 서브에이전트가 판정, 수정은 사용자 수용 후 메인 세션이 수행.
범위 조정: 정책과 Saga 축 감사는 사용자 지시로 제외했다 (그 단계는 Step 8 미진입). 해당 에이전트 결과는 폐기. 수행된 축은 DbC 계약 6축(에이전트 A)과 공통 3축(에이전트 C).
재검증: 이번이 06-4에 대한 1회차이며 반영 후 재실행하지 않는다 (스킬 규칙).

## 1. 판정 요약

에이전트 A (DbC 계약 축): 치명 2 / 보통 9 / 확인필요 4
에이전트 C (공통 축): 치명 1 / 보통 9 / 확인필요 3
겹침: 프로모션 update/close 무영향 부재, PricingService 계약 행 부재, 커맨드 이름 매핑 부재, RequestBooking 무해 표기 모순(A는 치명, C는 보통).

## 2. 주요 지적 (수용 판정 포함)

### 치명

| 출처 | 지적 | 사용자 판정 | 반영 |
|---|---|---|---|
| A | 재호출 무해가 애그리거트 메서드에만 걸려 있어, 무해 경로에서도 같은 트랜잭션의 재고 연산(commit, release)이 실행되어 선행조건 위반으로 롤백된다. 무해가 실제로는 실패 | 수용 | 0절 무해 정의에 재고 연산과 이벤트 발행 생략을 명시. confirm, expire, cancel의 Post를 전이 경로와 무해 경로 두 갈래로 분리. 메서드가 전이 발생 여부를 반환 |
| A | 0절 무해 적용 6곳 목록에 RequestBooking 멱등키 재요청이 없는데 계약표는 재호출 무해라 표기. 모순이며 재요청 시 이벤트 재발행 여부 미정 | 수용 | 종착 무해(6곳)와 멱등 반환(RequestBooking)을 별도 개념으로 분리. 멱등 반환 경로의 재고 선점과 이벤트 발행 생략을 Post에 명시 |
| C | 승인 유실 창: 확정과 환불 두 정책이 별도 핸들러로 각자 다른 시점에 가드를 평가하면, 환불이 HELD를 보고 침묵한 직후 TTL이 만료시키고 확정이 EXPIRED를 보고 거부해 승인이 어느 쪽에도 잡히지 않는다 | Step 8 이월 기록 (정책 영역 판정은 Step 8 소관이라는 방침) | 06-4 3절 이월 목록에 시나리오와 선택지 3개(한 핸들러 통합, expire 후행조건 확장, 순찰 정책 T2)를 기록 |

### 보통 (전부 수용)

| 출처 | 지적 | 반영 |
|---|---|---|
| A | A4 테스트 문장의 "언젠가"는 검사 불가 | 종료 상태 집합으로 문장 교체 |
| A | registerProperty 위반 예외 칸이 예외가 아니라 책임 위치 | Pre를 컨트롤러 소관으로 정리, 예외 없음 |
| A+C | expire의 결제 실패 경로에 재검사 가드 없음 (TTL 경로와 비대칭), 1-3 Guard 기준 행마다 상이 | expire Pre에 이벤트 탑재 시도 수 3 이상 재확인 추가, 1-3 Guard 전 행 잠금 후 상태 검사로 통일 |
| A | REQUESTED 갇힘(콜백 부재 시 탈출 불가)이 전이표에 미명시 | 결제 시도 전이표 아래 알려진 갇힘으로 명시, 수동 개입 대상 표기 |
| A+C | 프로모션 update/close에 스냅샷 무영향 부재, promotionName 문서 전체 부재 | 두 행 Post에 무영향(I4) 병기, RequestBooking Post에 스냅샷 구성(promotionName 포함) 명시 |
| A+C | PricingService 계약 행 부재. 캠페인 기간 규칙(양끝 포함, 생성 시점 판정)과 단수 규칙 미승계 | PricingService 행과 isApplicable 행 신설 |
| A+C | 커맨드 22개와 계약표 행 이름의 매핑 부재 (자립성 결손) | 1-2 머리에 매핑표 추가, source와 reason 값 열거 포함 |
| A | hold의 미개설과 재고 부족이 같은 예외로 뭉개짐 | InventoryNotOpened 분리 |
| A | expiresAt이 시간적 불변식 목록에 없음 | I4에 expiresAt 병기 |
| C | R1~R5 번호가 문서에 거의 등장하지 않아 역추적 불가 | A1, A2, U1에 R 태그, 3절에 역추적표 신설 |
| C | 동기 정책 세 행의 트리거(이벤트)와 일관성(같은 트랜잭션)이 시간적으로 모순 | 트리거 열을 트랜잭션 내부 호출로 정정, 이벤트는 커밋 후 발행되는 기록으로 표기 |
| C | Money 공유 커널 적합이 근거 없이 등장 | 06-1 후보 판정의 가설 해제라는 근거 병기 |

## 3. 요구사항 역추적 (두 에이전트 공통 결론)

R1, R2는 커버. R3, R4는 치명 지적과 연동된 부분 커버였고 치명 반영으로 닫힘. R5는 프로모션 쪽 무영향 부재로 부분 커버였고 보통 반영으로 닫힘. R4의 승인 유실 창만 Step 8 이월로 열려 있다.
