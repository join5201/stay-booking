# 결정표와 반영

최초 작성: 2026-09-21
최종 갱신: 2026-09-21 (신설. 이슈 189)

왜 이 파일이 필요한가: 리포트 A와 B가 들어온 뒤의 일은 양식 둘(harness/prompts/decision-table.md와 apply.md)과 CLAUDE.md 3절의 ID 규약과 check.mjs g2의 두 모드에 나뉘어 있다. 결정표 여섯 건을 만들며 매번 다시 모았다. 양식은 그대로 두고 순서만 여기 둔다.

## 1. 결정표 초안

| 순서 | 하는 일 | 근거 |
|---|---|---|
| 1 | 리포트 둘이 지정한 파일에 있는지 본다. harness/reviews/task-S{Step}-{키}-R{n}-A.md와 -B.md. 리포트 끝에 보조 표(원본 번호, 지적 ID, 심각도, 위반 기준)가 있고 판정 요약의 등급별 수와 같은지 본다. 없거나 어긋나면 잘린 리포트다. 0건으로 취급하지 않는다 | evaluate.md 5-1항, decision-table.md G2 절 |
| 2 | harness/prompts/decision-table.md의 현재 판을 harness/decisions/task-S{Step}-{키}-R{n}.md로 복사한다 | |
| 3 | 대상과 원본 표를 채운다. 대상 판과 해시, 계약 경로, 리포트 둘의 경로와 해시, 지적 수 둘, 전체 행 수 | |
| 4 | 원본 지적을 한 행씩 옮긴다. A 전부 뒤 B 전부. 원본 번호, 지적 ID, 심각도, 위치, 위반 기준, 원문 지적, 원문 근거를 그대로. 여러 줄이면 인용 블록으로 보존하고 ID로 잇는다. 요약하거나 빼지 않는다 | decision-table.md 지적별 결정 절 |
| 5 | 지적 ID는 S{Step}-R{라운드}-{A 또는 B}-{원본 번호 2자리}. 형식이 다르면 g2가 대조를 못 한다 | CLAUDE.md 3절 |
| 6 | 결정과 이유 열은 비운다. 사용자가 채운다 | |
| 7 | 정지. "결정표 준비 완료. 결정과 이유를 채워 달라." | |

사용자가 바꾸는 열은 결정과 이유뿐이다. 모델이 심각도를 낮추거나 행을 빼서 검사를 통과시키지 않는다. 사용자가 더한 지적은 아래 사용자 추가 지적 표에 U로 적고 위 표에 섞지 않는다.

## 2. 반영 전 G2

node harness/tools/check.mjs g2 결정표경로 --mode pre

| 보는 것 | 실패하면 |
|---|---|
| 대상과 계약과 리포트 둘의 판이 결정표와 같은가 | 판을 맞춘다. 대상을 다시 만들지 않는다 |
| 원본 ID 집합과 결정표 ID 집합이 같은가. 행 수가 합과 같은가 | 빠진 행을 옮긴다 |
| 모든 결정이 수용, 거부, 반박 중 하나인가 | 사용자에게 빈 행을 돌려준다 |
| 거부에 이유가 있는가. 반박은 확인필요에만 있는가 | 같음 |
| 치명 거부에 판단 기록(근거, 대안, 안티패턴, 사용자 결정, 날짜)이 있는가 | 같음 |

통과해도 확인자와 날짜를 결정표의 G2 확인 표에 남긴다. 결정표를 고친 뒤에는 이전 통과를 인정하지 않고 다시 돌린다.

## 3. 반영

정본은 harness/prompts/apply.md다. 반영 전 검사 여섯과 반영 일곱 단계가 거기 있다.

| 순서 | 하는 일 |
|---|---|
| 1 | 수용 항목만 허용 범위에 반영한다. 코드는 평가받은 기준 판에서 브랜치를 따고 diff를 보존한다. 문서는 별도 수정 후보 |
| 2 | 지적 ID마다 실제 변경 위치를 잇는다 |
| 3 | 미수용 항목이 무변경인지 diff로 대조한다. 수용과 미수용이 겹치면 관계를 보고하고 범위를 넓히지 않는다 |
| 4 | 문서는 g1 doc, 코드는 계약의 빌드와 테스트와 g1 code. 명령과 결과와 미실행을 남긴다 |
| 5 | harness/out/task-S{Step}-{키}-R{n}/applied/에 apply-report.md, apply.diff, 테스트 결과 사본 |
| 6 | 결정표의 반영과 최종 확인 인계 표를 채운다. 남은 실제 치명, 검증 미완료 |
| 7 | 정지. "반영 후보 완료. 승인을 기다린다." |

## 4. 최종

| 순서 | 하는 일 |
|---|---|
| 1 | R2가 필요하면 [eval-prep.md](eval-prep.md) 4절. 재평가는 최대 1회이고 소진은 완료 근거가 아니다 |
| 2 | node harness/tools/check.mjs g2 결정표경로 --mode final. 남은 치명과 반영본 검증을 여기서 본다 |
| 3 | 정지. "최종 확인 표 완료. 완료 판단을 기다린다." done은 사용자 판단 뒤에만 쓴다(N5) |
| 4 | 사용자가 완료를 확정하면 progress-row 스킬대로 done 행. 병합 전이면 그 브랜치 마지막 커밋, 병합 뒤면 다음 작업 브랜치 첫 커밋. 기록만을 위한 브랜치는 열지 않는다(CLAUDE.md 4-1 7단계) |
