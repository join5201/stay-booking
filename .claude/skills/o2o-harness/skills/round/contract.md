# 계약 초안

최초 작성: 2026-09-21
최종 갱신: 2026-09-21 (신설. 이슈 189)

왜 이 파일이 필요한가: 계약이 없으면 평가자에게 넘길 파일 목록을 정할 수 없다(HR1). 계약 아홉 건을 만들며 매번 양식 머리와 harness/tasks/README.md와 CLAUDE.md N9를 합쳐 읽었다. 그 순서를 한 자리에 둔다. 양식 자체는 harness/prompts/task-contract.md이고 여기서는 채우는 순서와 빠지기 쉬운 것만 적는다.

## 순서

| 순서 | 하는 일 | 근거 |
|---|---|---|
| 1 | 파일명을 정한다. 문서 Task는 task-S{Step}.md, 기능별 개발 Task는 task-S{Step}-{기능키}.md. 기능키는 10-6 기능별 API와 검증 연결 표의 구현 묶음 이름 | harness/tasks/README.md |
| 2 | harness/prompts/task-contract.md의 현재 판을 그대로 복사한다. 판 줄을 남긴다. 낡은 판으로 쓰면 fill이 경고하고 절이 빠지면 실패한다 | 양식 머리. 2026-09-08 task-S8이 v2에 멈춰 이틀 막혔다 |
| 3 | 빈칸을 채운다. 경로는 절대경로. 버전과 해시 칸은 손으로 적지 않는다 | HR2 |
| 4 | 허용 입력 표 둘을 가른다. 위는 생성자가 읽는 것, 아래(A와 B 평가 허용 입력)는 평가자에게 넘기는 것. 아래 표에 01 전체, 감사 문서, 이전 리포트, 결정표, harness/docs, harness/state, 생성 대화를 넣지 않는다 | HR1, N3 |
| 5 | 평가 대상 행은 경로와 해시 둘 다 생성 후 기입이라고 적는다. 이 작업 계약 행의 버전 칸은 자기 해시 없음이라고 적는다 | fill.self-hash. 계약 시점에 대상이 없다 |
| 6 | 정책 적용 표. 08-3 결정 11건과 API P01부터 P11 중 영향받는 것. 미결에 의존하는 구현을 확정하지 않는다 | N4 |
| 7 | 개발 Task는 선행 작업 칸에 앞 묶음이 백엔드와 테스트와 검증까지 내려갔는지 적는다 | N9 |
| 8 | node harness/tools/check.mjs fill 계약경로 통과. 유예 건수(생성 후 기입)를 확인한다 | HR2 |
| 9 | 정지. "계약 초안 완료. 승인을 기다린다." 승인은 계약의 승인과 진행 절에 사용자와 날짜로 남는다. 승인 전에는 생성으로 가지 않는다 | 양식 끝 문단 |

## 빠지기 쉬운 것

| 실수 | 왜 안 되나 |
|---|---|
| 값 칸에 설명을 덧붙인다 | 검사기가 읽는 칸은 값만 담는 자리다. 그 한마디가 값의 일부가 된다(CLAUDE.md 5-1) |
| 경로 칸에 폴더를 적는다 | 해시를 계산할 수 없다. fill이 실패한다 |
| 계약이 자기 자신을 가리킨다 | 해시를 적는 순간 파일이 바뀐다 |
| 생성용 표와 평가용 표를 같은 것으로 취급한다 | 감사 문서와 결정표가 평가 폴더로 들어간다 |
| 낡은 계약의 양식 판을 그대로 둔다 | 양식 판이 오르면 빠진 절을 채워야 fill이 통과한다 |

## 생성이 끝난 뒤

평가 대상 행의 생성 후 기입 두 칸을 실제 경로와 목록으로 바꾸고 fill을 다시 돌린다. 이 행이 아직 생성 후 기입이면 평가 준비로 가지 않는다. 그 다음은 [eval-prep.md](eval-prep.md)다.
