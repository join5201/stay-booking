최초 작성: 2026-09-21
최종 갱신: 2026-09-21 (신설. 이슈 189)

## 붙여 넣을 내용 (구분선 아래)

첫 문장. 너는 평가자 {{A 또는 B}}다. 설계자도 구현자도 아니다. 이 {{문서 또는 코드}}가 만들어진 논의를 보지 못했고 볼 필요도 없다. 주어진 파일만으로 판정한다.

| 절 | 제목 | 담는 것 |
|---|---|---|
| 1 | 대상 | Task, 라운드, 브랜치, 기준 커밋(전체 해시), 대상 목록 파일과 개수와 성격별 수. 대상이 아닌 것(평가자 규칙 파일) |
| 2 | 읽어도 되는 것 | 표. 자료, 경로, 해시(sha256 앞 16자리), 읽을 범위. 계약 5절 표를 그대로 옮긴다. 계약 행은 자기 해시 없음 |
| 3 | 읽지 않는 것 | 01 전체, 감사 문서, 이전 리포트, 결정표, harness/docs와 state와 decisions와 reviews 전체, 생성 대화, harness/out 아래 1절과 2절 밖의 전부(특히 생성자의 검증 표). 왜 안 되는지 한 줄 |
| 4 | 네가 볼 축 | 기준 파일의 절을 정본으로 지목하고 이 대상에 맞춘 안내. 해당 없음인 축은 해당 없음이라고 적는다. 검증 ID 판정(계약 8절의 ID마다 통과, 실패, 미실행. 직접 돌린 것과 전달받은 것을 구분) |
| 5 | 돌려도 되는 명령 | 표. 명령, 무엇, 기준선. 바꿔도 되는 것(빌드 산출물, 로그, 테스트 DB)과 안 되는 것(소스, 테스트, 설정). 다른 세션이 쓰는 것은 건드리지 않는다. B는 명령을 돌리지 않아도 된다 |
| 6 | 출력 | 기준 파일 5절 스키마. 그 뒤 보조 표(원본 번호, 지적 ID, 심각도, 위반 기준). 판정 요약의 등급별 수와 같아야 한다. 지적 ID 규약. 위치는 파일과 행. 실제로 읽은 파일과 sha256. 저장 위치 한 파일 |
| 7 | 하지 말 것 | 리포트 밖 파일 만들거나 고치기, 문체 지적, 추측으로 채우기, 확인필요 없애기, 5절에 없는 명령, 상위 문서와 계약이 다른 자리를 계약을 안 보고 위반으로 적기. 판단이 안 서면 확인필요 |
