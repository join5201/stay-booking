# O2O 문서 검토와 수정 내역

작성: 2026-09-07
기준: API 명세 v2, 로컬 개발과 검증 범위, Claude Code 생성과 Codex 평가 방식
상태: 문서 수정 완료. 실제 서비스 구현과 하네스 실행 검증은 미실행.

## 1. 검토 범위

설계 문서 01~06, 하네스 문서 10-4~10-6, 생성과 평가 및 반영 양식, 서비스 유형 학습 자료를 대조했다. API 명세는 독립적인 v2 문서로 유지했다.

Downloads의 과거 입력 팩과 PDF, 원격 FigJam, 임시 산출물은 수정 대상에서 제외했다. 학습 자료는 프로젝트 범위와의 혼동을 검토했으며 시장 동향과 예시 코드 전체의 정확성을 재검증한 것은 아니다.

## 2. 피드백과 수정

| 문제 | 영향 | 수정 |
|---|---|---|
| 모든 생성 문서에 3부 구조와 볼드 금지를 적용 | API 양식과 사용자가 요청한 가독성을 훼손 | 작업별 양식 적용. API는 요청과 응답 중심, 작성 과정 설명 제외 |
| 생성과 반영 요청이 설계 문서만 대상으로 함 | 코드와 테스트 변경을 인계할 수 없음 | 작업 유형, 기준 버전, 허용 파일과 실행 범위를 추가 |
| 평가 중 파일 작성 금지가 테스트 산출물까지 막음 | 실제 빌드와 테스트를 수행하기 어려움 | 소스는 변경하지 않고 승인한 빌드 출력, 로그와 테스트 DB만 변경하도록 구분 |
| 예시 미사용을 모든 JSON과 테스트 자료 금지로 읽을 수 있음 | API 계약과 테스트를 평가에 전달하지 못함 | 과거 평가 정답 예시와 서비스 JSON 및 fixture를 구분 |
| 작업별 입력 목록과 승인 기록의 양식이 없음 | 적용 정책과 완료 기준을 다시 해석해야 함 | task-contract.md 추가 |
| 재고와 요금의 기간 일괄 처리가 함께 적힘 | 명세에 없는 요금 일괄 API까지 구현할 수 있음 | 기간 일괄 등록은 재고에만 적용 |
| 구현 계획에 API와 검증 ID 연결이 없음 | 기능 누락과 테스트 범위 추적이 어려움 | 기능 묶음별 API ID와 T01~T30 연결 |
| PaymentStatus에 REFUNDED를 혼합 | 시도 승인 이력과 환불 결과가 충돌 | API의 PaymentAttempt와 Refund를 구분. 내부 애그리거트 구조는 미결 유지 |
| 검색 인원 조건의 비교 방향이 불명확 | 수용하지 못하는 객실을 검색할 수 있음 | maxOccupancy >= guestCount로 명시 |
| PromotionCreated에 상태 변경 없음이라고 표기 | 등록 이벤트와 조회를 혼동 | 운영자 등록 및 변경과 예약의 읽기 전용 조회를 분리 |
| 판매 준비에 동시성이 없다고 표기 | 재고 조정과 선점 경합을 놓침 | 수정 버전과 재고 선점의 경합 가능성 명시 |
| 승인 가드가 HELD 상태만 확인 | 스케줄러가 늦으면 TTL 이후 승인 가능 | 서버 시각을 함께 검사하고 만료 후 지연 승인은 환불하도록 연결 |
| 같은 트랜잭션을 미결과 확정으로 동시에 표현 | 구현자가 미결 설계를 확정으로 읽음 | 일관성 보장 대상과 트랜잭션 구현 후보를 구분 |
| 로컬 링크와 보드 영역 번호가 오래됨 | 없는 파일이나 다른 설계 영역을 참조 | 실제 로컬 파일 경로와 영역 6, 7로 정정 |
| 학습 자료의 상태와 기능을 현재 설계로 읽을 수 있음 | 배달, 채널 연동과 정산 등 범위 확대 | 학습 참고 성격과 현재 숙박 서비스 범위를 명시 |

## 4. 남은 항목

1. 사용할 설계 입력 버전과 첫 Task의 범위 확정. 로컬 01 v9는 v8을 수정한 것이며 과거 계획의 v19를 확보한 것은 아니다.
2. 원문에 의존하는 작업의 07과 실제 평가 기준 확보. 새 양식이 기존 DDD 스킬을 복원한 것은 아니다.
3. API의 P01~P11 중 첫 Task에 영향받는 정책 채택과 트랜잭션 및 Payment 모델의 미결 설계 정리.
4. 첫 기능에서 생성, 테스트, 평가, 사용자 결정, 반영과 최종 검증 실행.

## 5. 확인 범위

현재 문서 18개에서 로컬 링크 24개, 코드 블록 닫힘과 금지 기호를 검사했다. API 33개와 계약 테스트 30개의 ID 연결 및 문서 버전 표기를 대조했다. 자동 검사 오류는 없었고 API v2의 내용은 이번 수정 중 바뀌지 않았다.

양식은 문서와 코드 작업의 입력, 후보 저장, 검사와 실행 권한이 맞는지 검토했다. 코드 실행을 허용하더라도 평가자가 소스를 고치지 않는 조건과 최종 검증 미실행을 통과로 처리하지 않는 조건을 확인했다.

이 기록은 문서 간 일관성 검토 결과다. 실제 평가 스킬의 정식 평가나 서비스 테스트 통과 기록으로 사용하지 않는다.
