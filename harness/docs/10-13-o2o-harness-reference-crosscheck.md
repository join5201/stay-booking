# 하네스 대조 상대 다섯 (10-13)

최초 작성: 2026-09-09
최종 갱신: 2026-09-10 (ECC 축 설명에서 칸 수를 뺌. 칸이 열둘로 늘었다)

왜 이 파일이 필요한가: 이 하네스는 처음부터 혼자 설계했고 harness/docs/의 결정 이력은 전부 내부 근거만 인용한다. 규약과 게이트가 통상과 맞는지 잴 바깥 기준이 없다. 대조 상대를 고정해 두지 않으면 다음 세션이 또 검색부터 시작해서 다른 다섯을 고른다. 그러면 세션마다 다른 것과 비교하게 되고 비교가 쌓이지 않는다.

번호가 10-13인 이유: 7절 마지막 행에 적는다.

지위: 참고 자료이고 결정이 아니다. 여기 다섯은 아직 대조하지 않았다. 대조 결과가 규칙을 바꾸면 그 결정의 정본은 harness/decisions/다(harness/docs/README.md 마지막 줄).

근거: 2026-09-09 사용자 지시. 별 수와 저장소 정보는 같은 날 GitHub REST API 확인. 재현 방법은 6절.

## 1. 고르는 문제

하네스는 모델을 뺀 전부다. 파일 규약과 검사 스크립트와 기록 규칙과 프롬프트 양식이 하네스다(CLAUDE.md 1절). 그래서 대조 상대도 그 네 가지를 가진 저장소여야 한다. 별 수만으로 자르면 이 조건이 무너진다.

별 내림차순 그대로 자르면 아래가 먼저 온다. 전부 우리 다섯보다 별이 많고 전부 대조표의 칸이 빈다.

| 저장소 | 별 | 왜 뺐나 |
|---|---|---|
| DietrichGebert/ponytail | 132,692 | 코드를 적게 쓰게 만드는 스킬 하나. 규약도 게이트도 기록도 없다 |
| farion1231/cc-switch | 131,874 | 에이전트 계정 전환 데스크톱 앱. 도구이지 하네스가 아니다 |
| thedotmack/claude-mem | 93,547 | 세션 기억 하나만 다룬다. 네 부분 중 하나뿐이다 |
| NousResearch/hermes-agent | 243,612 | 에이전트 자체다. 우리가 만드는 것은 에이전트를 뺀 나머지다 |

## 2. 기준 셋

| 번호 | 기준 | 왜 |
|---|---|---|
| C1 | 하네스 네 부분 중 둘 이상을 가진다 | 하나뿐이면 대조표의 칸 대부분이 빈다 |

순서가 중요하다. C1과 C2로 먼저 거른 뒤에 C3을 적용한다. 반대로 하면 1절의 표가 답이 된다.

## 4. 대조 지점

저장소 전체를 읽는 것이 아니라 우리 어느 칸과 맞댈지 미리 정한다. 이 표가 이 문서의 본체다.

| 우리 칸 | 우리 파일 | 상대 | 무엇을 확인하나 |
|---|---|---|---|
| 규칙 문서 | CLAUDE.md 2절과 5절 | superpowers | 규칙을 한 파일에 모으는 우리 방식과 스킬 파일 여럿으로 쪼개는 방식 중 어느 쪽이 덜 새는가. 우리는 문체 규칙이 두 답변 연속으로 샌 기록이 있다(harness/docs/10-9) |
| 세션 기억 | harness/state/ 셋 | ECC | 세션 사이에 무엇을 남기고 무엇을 버리는가. progress.md 기록 칸이 과한지 모자란지 |
| 게이트 | harness/tools/check.mjs | promptfoo | 검사를 직접 스크립트로 짜는 것과 선언형 설정으로 두는 것의 차이. 검사 ID 이름과 실패 출력 형식을 볼 값어치가 크다 |
| 프롬프트 양식과 컨텍스트 예산 | harness/prompts/, .claude/settings.json의 autoCompactWindow | gsd-2 | 긴 작업에서 예산을 어떻게 나누는가. 우리 07 v3과 task-contract.md가 한 번에 얼마를 먹는지 |
| 권한 경계 | .claude/settings.json의 deny와 allow | gentle-ai | 권한을 도구가 아니라 설정으로 내리는 경계를 어디에 긋는가 |

우리 칸 다섯이 CLAUDE.md 1절의 하네스 네 부분을 다 덮는지 확인해 둔다.

| 하네스 부분 | 덮는 칸 |
|---|---|
| 파일 규약 | 규칙 문서, 권한 경계 |
| 검사 스크립트 | 게이트 |
| 기록 규칙 | 세션 기억 |
| 프롬프트 양식 | 프롬프트 양식과 컨텍스트 예산 |

## 6. 확인 방법

별 수는 시점값이라 다시 잴 수 있어야 한다.

실행 예시

    curl -s -H "User-Agent: o2o" https://api.github.com/repos/obra/superpowers

실패 시 출력 예시

    {"message":"API rate limit exceeded for 1.2.3.4.","documentation_url":"https://docs.github.com/rest/overview/rate-limits-for-the-rest-api"}

인증 없이 저장소 조회는 시간당 60회, 검색은 분당 10회다. 넘으면 위 출력이 나온다.

숫자가 그럴듯한지 보려면 눈금부터 확인한다. 같은 날 같은 방법으로 잰 값이다.

| 저장소 | 별 |
|---|---|
| react/react | 249,674 |
| torvalds/linux | 247,607 |
| anthropics/claude-code | 144,510 |

superpowers와 ECC가 react보다 위인 것은 오류가 아니다. 이 눈금 위의 값이다.
