# 세션별 worktree 분리

최초 작성: 2026-09-09
최종 갱신: 2026-09-09

왜 이 문서가 필요한가: 세 세션이 작업 트리 하나를 공유하는 동안 2026-09-09 하루에만 여섯 번 막혔다. 남의 미커밋 작업이 커밋에 쓸려 들어갔고, 브랜치를 못 바꿔 백업하고 되돌리기를 네 번 했다. 이 문서가 그 분리의 근거와 절차와 남는 제약을 적는다.

## 1. 무엇이 문제였나

작업 트리가 하나면 체크아웃된 브랜치도 하나다. 세션이 셋이면 셋이 그 하나를 두고 다툰다.

| 사고 | 언제 |
|---|---|
| 개발 세션이 경로를 안 적고 커밋해 문서 세션의 미커밋 작업이 쓸려 들어갔다 | 2026-09-08 PR 33 |
| 브랜치를 못 바꿔 작업을 트리에 올려 둔 채 대기 | 2026-09-09 네 번 |
| 병합된 산출물이 작업 트리에 없어 다음 단계가 막힘 | 2026-09-09 세 번 |

## 2. 왜 그동안 못 나눴나

계약의 경로 칸이 절대경로였다. 다른 폴더의 worktree에서 검사기를 돌려도 그 절대경로가 원래 폴더를 가리켜 남의 파일을 해시했다. 실패가 아니라 조용한 오답이라 더 나빴다.

이슈 26이 그것을 고쳤다. 검사기가 상대경로를 저장소 루트 기준으로 풀고, 루트는 스크립트 위치에서 유도한다. 그래서 트리마다 자기 파일을 본다.

2026-09-09 실측이다.

| 트리 | 검사기가 유도한 루트 |
|---|---|
| C:/Dev/potenup/99_projects/o2o | C:\Dev\potenup\99_projects\o2o |
| C:/Dev/potenup/99_projects/o2o-dev | C:\Dev\potenup\99_projects\o2o-dev |

## 3. 배치

| 트리 | 경로 | 누가 쓰나 |
|---|---|---|
| 본 트리 | C:/Dev/potenup/99_projects/o2o | 문서와 하네스 세션 |
| 개발 트리 | C:/Dev/potenup/99_projects/o2o-dev | 개발 세션 |

저장소 밖 형제 폴더로 둔 이유 둘이다. 상위 C:/Dev/potenup 저장소가 .gitignore의 /99_projects/ 규칙으로 이 폴더들을 안 본다. 그리고 저장소 안에 두면 .gitignore를 고쳐야 하고 검사기의 루트 유도가 자기 안의 트리를 만나 헷갈린다.

## 4. 만드는 절차

본 트리에서 한 줄이다.

    git worktree add ../o2o-dev <브랜치>

한 브랜치는 한 트리에만 체크아웃된다. 이미 다른 트리가 잡은 브랜치는 거부된다. 그것이 이 방식의 안전장치다.

## 5. 따라오지 않는 것

추적 제외 파일은 새 트리에 안 생긴다. 사람이 옮긴다.

| 파일 | 무엇 | 어떻게 |
|---|---|---|
| backend/.env | MySQL 접속값 | 본 트리에서 복사한다. deny 규칙이 모델의 접근을 막으므로 사람이 한다 |
| .claude/settings.local.json | 답변 형식 Stop 훅 | 필요하면 복사한다. 10-9 7절이 로컬 전용으로 결정했다 |
| backend/build, backend/.gradle | 빌드 산출물 | 새 트리에서 다시 빌드한다 |

env.example은 추적되므로 따라온다.

## 6. 남는 제약

| 제약 | 내용 |
|---|---|
| 기록 파일은 여전히 공유 | progress.md와 troubleshooting.md와 knowledge.md는 같은 파일이다. merge=union이 충돌을 막지만 순서는 보장되지 않는다 |
| 병합은 각 트리가 따로 | 한쪽에서 main이 갱신돼도 다른 트리는 자동으로 안 받는다. git merge origin/main을 각자 돌린다 |
| CLAUDE.md 1절의 루트 표기 | 본 트리 경로 하나만 적혀 있다. 트리가 둘이 된 사실은 이 문서가 정본이다 |
| 옛 브랜치의 절대경로 | 이슈 26 이전 브랜치는 계약에 절대경로가 남아 있다. main을 병합해야 상대경로 판이 온다 |

마지막 것이 개발 트리를 만든 직후 실제로 났다. feat/task-s9-catalog-skeleton이 PR 41 이전이라 계약에 절대경로 34곳이 남아 있었고 fill이 자기 해시 검사에서 걸렸다.

## 7. 세션이 지켜야 할 것

| 규칙 | 왜 |
|---|---|
| 자기 트리에서만 작업한다 | 남의 트리에 파일을 만들면 그 세션이 자기 것으로 착각한다 |
| 커밋할 때 경로를 명시한다 | CLAUDE.md 4-1. 트리를 나눠도 기록 파일은 공유라 여전히 필요하다 |
| 브랜치를 바꾸기 전에 git status를 본다 | 같은 트리 안에서는 여전히 하나만 체크아웃된다 |
| worktree 목록을 먼저 본다 | git worktree list. 어느 브랜치가 어디 잡혀 있는지가 거기 있다 |

이 판은 세션별 worktree 분리의 기록이다. 승인 전에는 확정본으로 인용하지 않는다.
