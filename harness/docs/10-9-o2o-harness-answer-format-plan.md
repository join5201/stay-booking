# 답변 형식 R1부터 R4를 프로젝트 전체에 적용하는 계획

최초 작성: 2026-09-08
최종 갱신: 2026-09-08 v4 (훅을 로컬 전용으로 결정. 6절 임계값 실측 종결, 7절 저장 위치와 근거, 8절과 9절 등재 자리, 12절 미결 넷에서 하나로)

왜 이 문서가 필요한가: R1부터 R4는 이미 두 곳에 적혀 있는데도 지켜지지 않았다. 규칙을 세 번째로 옮겨 적는 대신, 왜 새는지를 먼저 적고 재는 장치를 붙이는 순서를 여기 고정한다. 이 문서가 없으면 다음에도 문구 강화로 대응하고 같은 자리에서 다시 샌다.

## 2. 진단

두 줄이다.

첫째, 문서 산출물에는 자물쇠가 있고 답변에는 없다. g1이 문서의 날짜와 금지 기호와 종료 문장을 재는데, 답변을 재는 것은 아무것도 없다. 쉬운 말로, 규칙은 벽에 붙인 종이고 게이트는 문에 단 자물쇠다. 답변에는 종이만 붙어 있었다.

둘째, R1부터 R4는 기계로 잴 수 있는 정도가 서로 다르다.

| 번호 | 기계 판정 | 이유 |
|---|---|---|
| R1 결과 중심 | 못 잰다 | 무게중심은 글자 수로 안 나온다 |
| R2 문제와 원인과 해결책 | 지금은 못 잰다 | 자유 서술이라 낱말이 있어도 내용인지 모른다 |
| R3 ELI5 | 못 잰다 | 쉬운 말인지는 판단이다 |
| R4 결과 절 | 잰다 | 마지막 절 제목만 보면 된다 |

그래서 이 계획은 두 갈래다. 못 재는 것은 틀로 유도하고, 잴 수 있는 것에만 자물쇠를 단다.

핵심 수는 R2다. R2가 못 재는 이유는 자유 서술이기 때문이지 원리상 불가능해서가 아니다. 결과 절의 행을 고정하면 R2는 잴 수 있는 항목으로 바뀐다. 이 한 수가 게이트 범위를 하나에서 둘로 늘린다.

## 2-1. 정본을 어디 두는가 (2026-09-08 v2 신설)

v1은 R1부터 R4의 정본을 harness/prompts/answer-format.md로 옮기고 CLAUDE.md 2-1을 참조 한 줄로 줄이겠다고 적었다. 그것이 틀렸다.

CLAUDE.md는 세션마다 자동으로 읽힌다. harness/prompts/ 아래 파일은 누가 열어야 읽힌다. 규칙 본문을 자동으로 안 읽히는 자리로 옮기면 눈에 덜 띄게 된다. 안 지켜져서 고치는 작업이 안 지켜지기 더 쉬운 자리로 규칙을 옮기는 셈이다.

그래서 둘로 가른다. 기준은 길이가 아니라 자동으로 읽혀야 하는가다.

| 무엇 | 어디 | 이유 |
|---|---|---|
| R1부터 R4 네 줄 | CLAUDE.md 2-1에 그대로 둔다 | 짧고, 매 세션 자동으로 읽혀야 한다 |
| 등급과 골격과 결과 절 다섯 행과 게이트 규격 | harness/prompts/answer-format.md | 길고, 검사기와 훅이 읽으면 된다 |
| 둘의 연결 | CLAUDE.md 2-1에 참조 한 줄 | 규칙에서 규격으로 내려가는 길 |

CLAUDE.md는 늘지 않았다. 참조 문장을 기존 설명 문단 끝에 붙여 197줄 그대로다. 원래 노렸던 절약은 포기했지만 권고 안에 남는다. 산 것은 가시성이다.

## 4. 답변 등급 (2026-09-08 v2: 갑을병을 A B C로)

모든 답변에 결과 절을 요구하면 한 줄 확인에도 표를 달게 된다. 등급을 셋으로 가른다. A가 가장 높고 C가 가장 낮다. PTCF F1이 ReAct에 이미 같은 갈래를 두므로 형식이 같다.

| 등급 | 무엇 | 적용 |
|---|---|---|
| A | 파일을 만들거나 고치거나 게이트를 돌린 턴 | R1부터 R4 전부. 결과 절 필수 |
| B | 설계와 트레이드오프 판단에 답한 턴 | R1부터 R4 전부. ReAct와 결과 절 필수 |
| C | 확인, 예 아니오, 한 줄 사실 | R3만. 결과 절 면제 |

등급을 누가 정하는가가 다음 문제다. 사람이 매번 정할 수 없고, 모델이 정하면 자기 편한 쪽으로 정한다. 그래서 기계가 정한다. 판정 규칙은 6절에 둔다.

이 문서의 단계 이름은 8절에서 숫자를 쓴다. 등급이 A와 B와 C를 차지했기 때문이다. 같은 글자를 두 축에 쓰면 검사 출력과 커밋 메시지에서 어느 축인지 못 가른다.

## 5. 답변 골격

A와 B 등급의 절 골격이다. 못 재는 R1과 R3을 이 틀이 유도한다.

| 자리 | 내용 | 어느 규칙을 유도하나 |
|---|---|---|
| 첫 줄 | 결론 한 문장. 표도 제목도 아니다 | R1 |
| 본문 | 표 중심. 절 제목은 자유 | F3 |
| 본문 안 | 전문 용어를 처음 쓰는 자리마다 쉬운 말 한 줄 | R3 |
| 마지막 절 | 제목이 정확히 결과 | R4 |

결과 절의 행을 고정한다. 이것이 R2를 재는 항목으로 바꾸는 자리다.

| 항목 | 무엇을 적는가 |
|---|---|
| 문제 | 무엇이 잘못돼 있었나 |
| 원인 | 왜 그렇게 됐나 |
| 해결책 | 무엇으로 막았나 |
| 파일 변경 | 절대경로와 커밋 여부. 없으면 없음 |
| 다음에 필요한 것 | 사용자가 할 일 또는 다음 정지점 |

앞의 셋은 해당 없음을 허용한다. 상태 보고처럼 고친 것이 없는 턴이 있기 때문이다. 다만 해당 없음을 쓰려면 왜 해당 없는지를 같은 칸에 적는다. 빈칸을 편하게 채우는 구멍을 막는다.

## 6. 게이트 설계 (2026-09-08 v2: 등급 표기 A B C)

새 명령 하나다.

    node harness/tools/check.mjs answer <답변파일> [--grade A|B|C]

| 검사 ID | 무엇 | 적용 등급 |
|---|---|---|
| answer.grade | 등급 판정. --grade가 없으면 자동 | 전부 |
| answer.lead | 첫 줄이 문장인가. 표와 제목은 실패 | A, B |
| answer.result-section | 마지막 절 제목이 결과인가 | A, B |
| answer.result-rows | 결과 절에 다섯 행이 다 있는가 | A, B |
| answer.result-empty | 앞의 셋이 해당 없음일 때 이유가 붙었는가 | A, B |
| answer.no-emdash, answer.no-middot, answer.no-bold | 줄표와 가운뎃점과 제목 밖 볼드 | 전부 |

자동 등급 판정 규칙이다. 위에서부터 처음 맞는 행을 쓴다.

| 조건 | 등급 |
|---|---|
| 답변이 파일 경로를 쓴 적이 있다 | A |
| 답변에 Thought 또는 Observation 절이 있다 | B |
| 그 외이고 글자 수가 임계 미만 | C |
| 그 외 | B |

임계값은 1200자다. 2026-09-08 실측으로 닫았다.

표본 여섯을 쟀다. 이 세션의 실제 답변 셋과 fixture 셋이다.

| 표본 | 글자 수 | 경로 언급 | ReAct | 등급 |
|---|---|---|---|---|
| PR 21 머지 보고 | 1001 | 있음 | 없음 | A |
| 훅 실측 보고 | 1840 | 있음 | 없음 | A |
| 탐침 | 1187 | 있음 | 없음 | A |
| fixture A | 802 | 있음 | 없음 | A |
| fixture B | 906 | 없음 | 있음 | B |
| fixture C | 108 | 없음 | 없음 | C |

임계값이 실제로 쓰이는 경우가 거의 없다는 것이 측정에서 나온 것이다. 임계값은 경로도 ReAct도 없는 답변에만 걸리는데, 무언가를 한 턴은 거의 예외 없이 경로를 쓰므로 그 전에 A로 잡힌다. 여섯 중 임계값 판정까지 내려간 것은 108자짜리 하나뿐이다.

그 밴드의 표본과 임계값 사이가 108자 대 1200자로 열 배 넘게 벌어져 있어 오탐이 나올 여지가 좁다. 값을 바꿀 근거가 없으므로 1200자를 유지한다. 앞으로 오탐이 나오면 harness/state/troubleshooting.md에 적고 그때 조정한다. 조정 근거가 생기기 전에는 손대지 않는다.

## 7. 훅 연결

Stop 훅이다. 답변이 끝난 뒤 돌고, last_assistant_message로 답변 텍스트를 받는다.

| 확인한 것 | 값 | 출처 |
|---|---|---|
| 입력 필드 | session_id, transcript_path, cwd, hook_event_name, last_assistant_message 등 | https://code.claude.com/docs/en/hooks (2026-09-08 확인) |
| 막을 수 있나 | exit 2로 정지를 막고 대화를 계속시킨다 | 같음 |
| 되먹임 | additionalContext로 텍스트를 넘긴다 | 같음 |
| 저장 위치 | .claude/settings.local.json. .gitignore 17행이 제외하므로 이 기계에만 적용된다 | 2026-09-08 결정. 아래 |

저장 위치를 settings.json에서 settings.local.json으로 바꾼 이유 (2026-09-08 결정). settings.json은 저장소 파일이라 넣는 순간 다른 기계에서도 켜진다. 이 훅은 정지를 막는 물건이고 그 동작을 실측한 사람은 이 기계에 있다. 켜 본 적 없는 기계에서 자동으로 켜지면, 훅이 고장 났을 때 원인을 모르는 사람이 세션이 멈추는 것부터 겪는다. 로컬에 두면 켠 사람이 결과를 안다. 대가는 다른 기계에서 게이트가 자동으로 돌지 않는다는 것이고, 그 자리는 check.mjs answer를 손으로 돌려 메운다.

2026-09-08 실측으로 닫았다. 이어 붙이는 쪽이다. 정지를 막으면 앞 답변이 그대로 남고 모델이 그 뒤에 이어 쓴다. 그래서 훅이 다시 답하라고 적으면 답변이 통째로 두 번 나온다. 문구를 빠진 것만 이어서 내라로 바꿔 이 성질에 맞췄다. 차단 한도의 기준도 session_id에서 prompt_id로 바꿨다. 세션으로 세면 세션당 한 번밖에 못 고치고, 턴으로 세면 무한 반복만 막으면서 매 턴 고칠 수 있다.

마지막 행이 이 계획의 한계다. 기계는 결과 절이 있는지는 재지만 그 안이 진짜인지는 못 잰다. 그 자리는 사람이 본다.
