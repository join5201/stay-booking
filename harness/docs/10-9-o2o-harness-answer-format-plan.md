# 답변 형식 R1부터 R4를 프로젝트 전체에 적용하는 계획

최초 작성: 2026-09-08
최종 갱신: 2026-09-08

왜 이 문서가 필요한가: R1부터 R4는 이미 두 곳에 적혀 있는데도 지켜지지 않았다. 규칙을 세 번째로 옮겨 적는 대신, 왜 새는지를 먼저 적고 재는 장치를 붙이는 순서를 여기 고정한다. 이 문서가 없으면 다음에도 문구 강화로 대응하고 같은 자리에서 다시 샌다.

## 1. 확인한 사실 (2026-09-08)

| 사실 | 근거 |
|---|---|
| R1부터 R4가 CLAUDE.md 2-1에 있다 | CLAUDE.md:62 |
| 같은 내용이 PTCF v2 Format 절에도 있다 | harness/prompts/harness-ptcf-prompt.v2.md:103 |
| 그런데도 2026-09-08 세션에서 R3이 두 답변 연속으로 어긋났다 | 사용자 지적 |
| CLAUDE.md가 197줄이고 공식 권고가 200줄이다 | wc -l, https://code.claude.com/docs/en/memory |
| CLAUDE.md는 강제 장치가 아니라고 스스로 적는다 | CLAUDE.md 머리말 |
| Stop 훅이 답변 텍스트를 받고 정지를 막을 수 있다 | https://code.claude.com/docs/en/hooks (2026-09-08 확인) |
| 훅 연결의 선행 조건인 검사기 안정이 충족됐다 | harness/prompts/harness-ptcf-prompt.md:325, 테스트 49건 |

## 2. 진단

두 줄이다.

첫째, 문서 산출물에는 자물쇠가 있고 답변에는 없다. g1이 문서의 날짜와 금지 기호와 종료 문장을 재는데, 답변을 재는 것은 아무것도 없다. 쉬운 말로, 규칙은 벽에 붙인 종이고 게이트는 문에 단 자물쇠다. 답변에는 종이만 붙어 있었다.

둘째, R1부터 R4는 기계로 잴 수 있는 정도가 서로 다르다.

| 번호 | 기계 판정 | 이유 |
|---|---|---|
| R1 결과 중심 | 못 잰다 | 무게중심은 글자 수로 안 나온다 |
| R2 문제와 원인과 해결책 | 지금은 못 잰다 | 자유 서술이라 낱말이 있어도 내용인지 모른다 |
| R3 ELI5 | 못 잰다 | 쉬운 말인지는 판단이다 |
| R4 결과 절 | 잰다 | 마지막 절 제목만 보면 된다 |

그래서 이 계획은 두 갈래다. 못 재는 것은 틀로 유도하고, 잴 수 있는 것에만 자물쇠를 단다.

핵심 수는 R2다. R2가 못 재는 이유는 자유 서술이기 때문이지 원리상 불가능해서가 아니다. 결과 절의 행을 고정하면 R2는 잴 수 있는 항목으로 바뀐다. 이 한 수가 게이트 범위를 하나에서 둘로 늘린다.

## 3. 적용 범위

프로젝트 전체라는 말의 경계를 먼저 긋는다. 안 그으면 규칙 둘이 같은 산출물에 걸린다.

| 대상 | R1부터 R4 적용 | 이유 |
|---|---|---|
| Claude Code 세션이 사용자에게 내는 답변 | 적용 | 이 규칙이 겨냥한 것 |
| document/의 설계 문서 | 적용 안 함 | F1부터 F16과 g1이 이미 덮는다 |
| Codex 평가 리포트 | 적용 안 함 | eval-criteria-ddd.md의 출력 스키마가 정본 |
| 커밋 메시지와 PR 본문 | 적용 안 함 | CLAUDE.md 4-1이 덮는다 |
| harness/state/의 기록 행 | 적용 안 함 | 아홉 칸 형식이 정본 |

## 4. 답변 등급

모든 답변에 결과 절을 요구하면 한 줄 확인에도 표를 달게 된다. 등급을 셋으로 가른다. PTCF F1이 ReAct에 이미 같은 갈래를 두므로 형식이 같다.

| 등급 | 무엇 | 적용 |
|---|---|---|
| 갑 | 파일을 만들거나 고치거나 게이트를 돌린 턴 | R1부터 R4 전부. 결과 절 필수 |
| 을 | 설계와 트레이드오프 판단에 답한 턴 | R1부터 R4 전부. ReAct와 결과 절 필수 |
| 병 | 확인, 예 아니오, 한 줄 사실 | R3만. 결과 절 면제 |

등급을 누가 정하는가가 다음 문제다. 사람이 매번 정할 수 없고, 모델이 정하면 자기 편한 쪽으로 정한다. 그래서 기계가 정한다. 판정 규칙은 6절에 둔다.

## 5. 답변 골격

갑과 을 등급의 절 골격이다. 못 재는 R1과 R3을 이 틀이 유도한다.

| 자리 | 내용 | 어느 규칙을 유도하나 |
|---|---|---|
| 첫 줄 | 결론 한 문장. 표도 제목도 아니다 | R1 |
| 본문 | 표 중심. 절 제목은 자유 | F3 |
| 본문 안 | 전문 용어를 처음 쓰는 자리마다 쉬운 말 한 줄 | R3 |
| 마지막 절 | 제목이 정확히 결과 | R4 |

결과 절의 행을 고정한다. 이것이 R2를 재는 항목으로 바꾸는 자리다.

| 항목 | 무엇을 적는가 |
|---|---|
| 문제 | 무엇이 잘못돼 있었나 |
| 원인 | 왜 그렇게 됐나 |
| 해결책 | 무엇으로 막았나 |
| 파일 변경 | 절대경로와 커밋 여부. 없으면 없음 |
| 다음에 필요한 것 | 사용자가 할 일 또는 다음 정지점 |

앞의 셋은 해당 없음을 허용한다. 상태 보고처럼 고친 것이 없는 턴이 있기 때문이다. 다만 해당 없음을 쓰려면 왜 해당 없는지를 같은 칸에 적는다. 빈칸을 편하게 채우는 구멍을 막는다.

## 6. 게이트 설계

새 명령 하나다.

    node harness/tools/check.mjs answer <답변파일> [--grade 갑|을|병]

| 검사 ID | 무엇 | 적용 등급 |
|---|---|---|
| answer.grade | 등급 판정. --grade가 없으면 자동 | 전부 |
| answer.lead | 첫 줄이 문장인가. 표와 제목은 실패 | 갑, 을 |
| answer.result-section | 마지막 절 제목이 결과인가 | 갑, 을 |
| answer.result-rows | 결과 절에 다섯 행이 다 있는가 | 갑, 을 |
| answer.result-empty | 앞의 셋이 해당 없음일 때 이유가 붙었는가 | 갑, 을 |
| answer.forbidden | 줄표와 가운뎃점과 제목 밖 볼드 | 전부 |

자동 등급 판정 규칙이다. 위에서부터 처음 맞는 행을 쓴다.

| 조건 | 등급 |
|---|---|
| 답변이 파일 경로를 쓴 적이 있다 | 갑 |
| 답변에 Thought 또는 Observation 절이 있다 | 을 |
| 그 외이고 글자 수가 임계 미만 | 병 |
| 그 외 | 을 |

[추측] 글자 수 임계값을 얼마로 둘지는 실측 없이 못 정한다. 지난 세션의 답변 원문이 저장소에 없어 표본을 뜰 수 없다. 첫 판은 1200자로 두고, 오탐이 나오면 harness/state/troubleshooting.md에 적어 조정한다. 임계값은 이 문서 12절 미결이다.

## 7. 훅 연결

Stop 훅이다. 답변이 끝난 뒤 돌고, last_assistant_message로 답변 텍스트를 받는다.

| 확인한 것 | 값 | 출처 |
|---|---|---|
| 입력 필드 | session_id, transcript_path, cwd, hook_event_name, last_assistant_message 등 | https://code.claude.com/docs/en/hooks (2026-09-08 확인) |
| 막을 수 있나 | exit 2로 정지를 막고 대화를 계속시킨다 | 같음 |
| 되먹임 | additionalContext로 텍스트를 넘긴다 | 같음 |
| 저장 위치 | .claude/settings.json. 저장소에 있으므로 프로젝트 전체에 적용된다 | 이미 있는 파일 |

[추측] 정지를 막았을 때 모델이 답변을 다시 쓰는지, 뒤에 이어 붙이는지는 문서 문장만으로 확정 못 한다. 문서는 계속한다고만 적는다. 이어 붙이는 쪽이면 결과 절이 두 번 나오는 답변이 되어 게이트의 값이 절반으로 떨어진다. 검증 방법은 B1 단계에서 일부러 결과 절 없는 짧은 답변을 한 번 내 보고 그 뒤에 무엇이 오는지 보는 것이다. 이 확인 전에는 훅을 settings.json에 정식 등재하지 않는다.

| 순서 | 무엇 |

커밋을 넷으로 가르는 기준은 되돌릴 수 있는 단위다.

| 커밋 | 내용 | 이것만 되돌리면 |
|---|---|---|

검사기와 그 테스트는 같은 커밋이다. 검사기와 그것이 잡아낸 산출물 수정은 다른 커밋이다. CLAUDE.md 4-1의 문장 그대로다.

## 10. 예상 실패와 막는 법

| 실패 | 징후 | 막는 법 |
|---|---|---|
| 오탐으로 단답까지 막힌다 | 짧은 확인 답변이 끝나지 않는다 | 6절 병 등급 면제. 임계값은 실측으로 조정 |
| 훅이 다시 쓰지 않고 이어 붙인다 | 결과 절이 두 번 나온다 | B1에서 먼저 잰다. 그러면 B3을 안 한다 |
| 규칙 사본이 셋이 된다 | answer-format.md와 CLAUDE.md와 PTCF에 같은 표 | A1과 A2와 A3을 한 커밋에 넣는다 |
| PR 17과 충돌 | 같은 파일이 양쪽에서 바뀐다 | PR 17 병합 뒤 시작 |
| 골격이 답변을 길게 만든다 | 병 등급 답변에도 표가 붙는다 | 4절 등급 갈래가 막는다. 안 되면 골격을 줄인다 |
| 게이트가 형식만 보고 통과시킨다 | 결과 절은 있는데 내용이 빈껍데기 | 5절 해당 없음 규칙과 answer.result-empty 검사 |

마지막 행이 이 계획의 한계다. 기계는 결과 절이 있는지는 재지만 그 안이 진짜인지는 못 잰다. 그 자리는 사람이 본다.
