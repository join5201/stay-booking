## 0. 이 문서의 성격

같은 단어가 자리에 따라 다른 것을 가리키는 지점의 수집이다. 정의는 여기서 확정하지 않는다. 경계 없이 정의를 확정하면 전역 사전이 되고, 전역 사전은 한 단어에 정의 하나를 강요해 충돌을 지운다. 충돌이 곧 경계 후보라는 신호를 살리기 위해 탐지(4-1)와 정의 확정(4-3)을 갈랐다. 이 표의 충돌이 05-2의 경계 판정 근거가 됐다.

## 1. 컨텍스트를 넘나들며 뜻이 갈리는 용어 (2026-09-02 v8: 이용자 표기 반영)

한 단어가 여러 컨텍스트에서 다른 것을 가리킨다. 코드에서 반드시 이름을 갈라야 하는 것들이다. 컨텍스트 열의 검색은 읽기 모델이지만 용어 충돌을 보이기 위해 같은 열에 둔다.

| 한국어 | 컨텍스트 | 영문 | 정의 |
|---|---|---|---|
| 객실 | 숙소 카탈로그 | RoomType | 호스트가 판매 단위로 등록한 객실 종류. 이름, 사진, 최대 인원을 가진다 |
| 객실 | 재고와 요금 | DailyInventory | 특정 날짜에 팔 수 있는 객실 수. 숫자만 있다 |
| 객실 | 예약 | roomTypeId | 예약 대상을 가리키는 식별자 |
| 가격 | 재고와 요금 | Rate | 호스트가 등록한 날짜별 단가. 언제든 조정할 수 있다 |
| 가격 | 예약 | Price | 요금에 프로모션을 적용해 계산한 결과. 예약 생성 시 스냅샷으로 동결 (v6: 확정에서 생성으로) |
| 가격 | 결제 | Amount | 실제로 PG에 청구한 액수 |
| 상태 | 예약 | BookingStatus | HELD, CONFIRMED, CANCELED, EXPIRED |
| 상태 | 결제 | PaymentStatus | REQUESTED, APPROVED, FAILED, REFUNDED |
| 확정 | 재고와 요금 | Commit | heldCount를 soldCount로 옮기는 것 |
| 확정 | 예약 | Confirm | 결제 승인으로 예약이 성립하는 것 |
| 반환 | 재고와 요금 | Release | heldCount 또는 soldCount를 내리는 것. 예약 쪽의 해제(ReleaseHold)는 v5에서 ExpireBooking에 흡수되어 사라졌다 |
| 지역 | 숙소 카탈로그 | Region | 숙소가 속한 행정 구역. 카탈로그가 소유 |
| 지역 | 프로모션 | Region | 적용 조건의 하나. 카탈로그의 값을 읽어 판정 |
| 지역 | 검색 | Region | 검색 필터. 카탈로그의 값을 읽음 |
| 기간 | 프로모션 | campaignPeriod | 프로모션이 유효한 달력상 기간. 양끝 포함 (v8: 05-3 정의 참조) |
| 기간 | 예약 | StayPeriod | 체크인부터 체크아웃까지의 숙박 기간. 반열림 |
| 선점 | 재고와 요금 | Hold (heldCount) | 특정 날짜의 heldCount를 1 올리는 수량 연산. 누가 잡았는지 모른다 (v4 추가) |
| 선점 | 예약 | HELD | Booking의 상태. 이용자 하나가 숙박 기간 전체를 결제 전까지 붙잡고 있고 TTL이 돈다 (v5: Hold 애그리거트가 아니라 BookingStatus) |
| 인원 | 숙소 카탈로그 | maxOccupancy | 객실 타입이 수용할 수 있는 상한 (v4 추가) |
| 인원 | 예약 | userCount | 이 예약으로 실제 묵는 사람 수 (v8: guestCount에서 개명) |
| 인원 | 검색 | userCount | 필터 조건. maxOccupancy 이상인 객실 타입만 보여준다 (v8: 개명) |
| 정책 | 프로모션 | Promotion | 운영자가 만든 자동 적용 할인 규칙. 데이터다 (v7 추가) |
| 정책 | 설계 전반 | Policy | 이벤트에 반응해 커맨드를 보내는 자동화 규칙. 프로세스다 (v7 추가) |

가격 셋을 구분하지 않으면 확정 금액이 이후 요금 변경에 영향받지 않는다는 요구사항을 코드로 표현할 수 없다.
상태 둘을 구분하지 않으면 외부 PG의 모델이 우리 예약 상태를 오염시킨다.
확정이 재고와 예약에서 다른 영어를 갖는 것은 의도적이다. 재고의 Commit은 수량 이동이고 예약의 Confirm은 계약 성립이다.
선점은 재고 쪽에서는 Hold라는 수량 연산이고 예약 쪽에서는 HELD라는 상태다. 재고는 예약을 모른다.
정책은 블라인드 재도출에서 지적된 3중 의미(할인 규칙 데이터, 반응 규칙, 액터)를 가른 것이다. 코드에서 프로모션 쪽 클래스에 Policy라는 이름을 쓰지 않는다. (v7)
이용자(User)는 예약하는 쪽만 가리킨다. 호스트와 운영자를 포함하는 넓은 뜻으로 쓰지 않는다. (v8)
