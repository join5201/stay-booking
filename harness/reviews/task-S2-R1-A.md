## 직접 확인한 결과와 전달받은 결과

| 구분 | 항목 | 결과와 한계 |
|---|---|---|
| 직접 확인 | 요청서와 허용 입력 열람 | 요청서 전문, 입력 여섯 파일의 허용 범위를 읽었다. 문서의 인용 링크, 메모리, 과거 리포트, 결정표, 생성 대화, harness/state, harness/docs는 열지 않았다 |
| 직접 확인 | 버전 대조 | 여섯 파일의 SHA-256을 계산했고 요청서의 값과 대조했다. 재개 후 재계산한 값도 같았다 |
| 직접 확인 | 문서 평가 | 03의 지정 여섯 축과 보드 이름 57개의 대조를 수행했다. 문서 내 근거에 따른 평가이며 코드나 런타임 동작 검증이 아니다 |
| 직접 확인 | 리포트 형식 | 상세 표 6열, 요구사항 역추적표 3열, 지적 보조 표 4열을 유지했다. 요약과 보조 표의 등급별 수를 대조했고 커맨드 27행, 이벤트 30행을 확인했다 |
| 생성자가 전달한 결과 | G1 | 요청서 5절은 두 후보가 g1 doc 각 9건을 통과했다고 적었다. 계약 10절 206행도 후보 2종의 통과를 적었다. 평가자가 직접 실행하거나 로그를 읽은 결과가 아니다 |
| 미실행 | node harness/tools/check.mjs fill harness/tasks/task-S2.md | 평가자는 계약을 수정할 수 없고, 해당 도구와 계약 원본 경로는 이번 평가의 허용 입력 밖이다. 대신 허용 사본의 해시를 읽기 방식으로 대조했다 |
| 미실행 | node harness/tools/check.mjs g1 <후보> --type doc --end | 검증 도구 파일은 여섯 허용 입력에 포함되지 않아 실행하지 않았다. 생성자의 통과 기재를 재현 결과로 바꾸지 않았다 |
| 미실행 | node harness/tools/check.mjs g2 <결정표> --mode pre 및 --mode final | 도구와 결정표가 허용 입력 밖이며, 결정 반영이나 완료 승인도 이번 평가자 역할에 없다 |
| 미실행 | 코드 실행, 테스트, DB 검증 | 설계 문서 평가다. 계약의 테스트 DB와 계약 테스트 ID도 해당 없음이다 |

요청서와 계약을 처음 열 때는 읽기용 Get-Content를 사용했고, 이후 허용 파일 읽기와 SHA-256 계산에는 Node 파일 API를 사용했다. 계약의 검증 명령을 다른 명령으로 대체 실행하지 않았다. 입력 읽기와 지정 리포트 저장 외에 소스, 테스트, 후보, 계약, 결정표, 진행 기록을 변경하지 않았다. 계약의 progress.md 기록 지시는 이번 요청의 쓰기 범위 밖이므로 이 리포트에 미실행 사유를 남겼다.
