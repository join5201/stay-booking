## 반영 전 검사

- 평가 대상, Task와 원본 리포트의 버전이 일치해야 한다.
- 원본의 모든 지적이 결정표에 있어야 한다. 삭제, 중복과 다른 라운드 혼입을 확인한다.
- 원본 번호, 심각도, 위치, 위반 기준, 지적과 근거가 보존돼야 한다.
- 결정은 수용, 거부, 반박 중 하나다. 빈 결정은 허용하지 않는다.
- 거부에는 이유가 있어야 하고 반박은 확인필요 등급에만 허용한다.
- 치명 오판은 근거, 대안, 안티패턴과 사용자 판단이 있어야 한다.

실패하면 대상을 수정하지 않고 해당 행과 원인을 보고한다.

## 반영과 검사

1. 수용한 변경만 허용 범위에 반영한다.
2. 문서는 별도 수정 후보를 저장한다. 코드는 평가받은 기준 버전에서 변경하고 diff를 보존한다.
3. 각 지적 ID와 실제 변경 위치를 연결한다.
4. 미수용 항목에 변화가 없는지 대조한다. 수용 항목과 미수용 항목이 겹치면 관계를 보고하고 범위를 임의로 넓히지 않는다.
5. 문서는 승인한 양식과 필수 항목을 검사한다. 3부 구조를 모든 문서에 강제하지 않는다.
6. 코드는 Task가 허용한 환경과 테스트 DB에서 관련 테스트, 빌드와 코드 검사를 수행한다. 명령, 결과와 미실행 항목을 남긴다.
7. 최종 버전, diff, 지적별 반영 결과와 남은 문제를 사용자에게 보고한다.

코드에 문서 형식을 적용하지 않는다. 허용하지 않은 환경이나 테스트 DB를 변경하지 않는다. 별도 LLM API와 앱 간 자동 호출은 사용하지 않는다.

## 재평가와 완료

- R1 반영본은 새 Codex 작업에서 R2 평가한다. 자료 전달은 사용자가 수행한다.
- 재평가는 최대 1회다. R2 이후 수정한 내용도 검증해야 한다.
- 실제 치명이 남거나 최종 변경본의 검증이 없으면 미완료다.
- 오판 정정과 실제 결함을 감수하는 판단을 구분한다.
- 사용자가 최종 후보를 승인한 뒤 확정본과 진행 기록을 갱신한다. 평가 횟수 소진을 완료 근거로 사용하지 않는다.
