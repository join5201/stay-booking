# 답변 형식 규격

최초 작성: 2026-09-08
최종 갱신: 2026-09-14 v3 (등급 S 신설. 결정 쟁점을 구하는 턴은 여섯 칸 양식이 결과 절을 대체한다. 이슈 147)
정본 관계: 규칙 R1부터 R5의 정본은 CLAUDE.md 2-1이다. 이 파일은 그 규칙을 어떤 틀과 어떤 검사로 지키는지의 규격이다.
근거: harness/docs/10-9-o2o-harness-answer-format-plan.md

왜 이 파일이 필요한가: R1부터 R4는 규칙으로만 있을 때 두 답변 연속으로 샜다. 규칙을 반복해 적는 대신 지킬 수밖에 없는 틀과 기계로 재는 항목을 여기 둔다. 이 파일이 없으면 다음에도 문구를 강화하고 같은 자리에서 다시 샌다.

## 1. 적용 범위

| 대상 | 적용 | 이유 |
|---|---|---|
| Claude Code 세션이 사용자에게 내는 답변 | 적용 | 이 규격이 겨냥한 것 |

두 규칙이 한 산출물에 겹치면 어느 쪽을 어겼는지 가릴 수 없다. 그래서 경계를 먼저 긋는다.

## 2. 등급 (2026-09-14 S 추가)

A가 가장 높고 C가 가장 낮다. 모든 답변에 결과 절을 요구하면 한 줄 확인에도 표가 붙기 때문에 셋으로 가른다. S는 순위 밖이다. 다른 골격을 쓰는 등급이고 글자에 뜻은 없다.

| 등급 | 무엇 | 적용 |
|---|---|---|
| A | 파일을 만들거나 고치거나 게이트를 돌린 턴 | R1부터 R4 전부. 결과 절 필수 |
| B | 설계와 트레이드오프 판단에 답한 턴 | R1부터 R4 전부. ReAct와 결과 절 필수 |
| C | 확인, 예 아니오, 한 줄 사실 | R3만. 결과 절 면제 |
| S | 사용자에게 결정 쟁점을 구하는 턴. 파일을 고치지 않은 턴 | R1과 R3과 3-1절 여섯 칸 양식(R5). 결과 절, ReAct, 남은 단계 표, 진척 표 면제 |

등급은 기계가 정한다. 모델이 정하면 자기 편한 쪽으로 정한다. 판정 규칙은 4절이다.

S가 왜 필요한가(2026-09-14): 판단 턴 하나에 결과 절 다섯 행과 ReAct와 남은 단계 표와 진척 표가 겹쳐 붙어 답변이 길어지고, 근거가 흩어져 대조가 어렵고, 이해 못 한 개념이 쌓여 승인 기준이 흐려지고, 구현 방향 승인과 정확성 검증이 구분되지 않았다. 사용자 제안이고 같은 날 결정 1로 대체를 승인했다. 얹지 않는다. S 턴에 결과 절을 같이 붙이면 검사에 걸린다.

S의 경계: 파일을 고친 턴은 A로 보고하고 멈춘다. 계속할까요 같은 진행 확인은 A의 다음에 필요한 것 행으로 족하다. S는 결정 쟁점에만 쓴다.

## 3. 골격

A와 B 등급의 절 골격이다. 기계로 못 재는 R1과 R3을 이 틀이 유도한다.

| 자리 | 내용 | 유도하는 규칙 |
|---|---|---|
| 첫 줄 | 결론 한 문장. 표도 제목도 아니다 | R1 |
| 본문 | 표로 정리 가능한 것은 표로 | R1 |
| 본문 안 | 전문 용어를 처음 쓰는 자리마다 쉬운 말 한 줄 | R3 |
| 마지막 절 | 제목이 정확히 결과 | R4 |

결과 절의 행은 고정이다. 자유 서술이면 R2를 기계가 못 재지만 행 이름이 고정이면 잰다.

| 항목 | 무엇을 적는가 |
|---|---|
| 문제 | 무엇이 잘못돼 있었나 |
| 원인 | 왜 그렇게 됐나 |
| 해결책 | 무엇으로 막았나 |
| 파일 변경 | 절대경로와 커밋 여부. 없으면 없음 |
| 다음에 필요한 것 | 사용자가 할 일 또는 다음 정지점 |

앞의 셋은 해당 없음을 쓸 수 있다. 고친 것이 없는 상태 보고 턴이 있기 때문이다. 다만 왜 해당 없는지를 같은 칸에 적는다. 이유 없는 해당 없음은 빈칸을 편하게 채우는 구멍이다.

### 3-1. S 등급 골격 (2026-09-14 신설)

절 제목은 승인 요청이다. 번호를 붙여도 된다(승인 요청 2). 첫 줄은 A와 B처럼 결론 한 문장이다. 그 아래 표 하나에 여섯 행을 고정한다. 결과 절은 두지 않는다. 이 양식이 그 자리를 대신한다.

| 칸 | 무엇을 적는가 |
|---|---|
| 결정 | 이번에 판단할 쟁점 하나. 권고가 있으면 같은 칸에 |
| 기존 기준과의 관계 | 준수, 변경, 신규 중 하나로 시작한다. 준수인 부분은 짧게 표시만 하고 변경과 신규를 중심으로 쓴다 |
| 이유 | 그 선택이 필요한 이유 |
| 근거 | 관련 기준과 원문 구절과 정확한 위치(경로:줄 또는 문서 번호와 절). 확인하지 못한 근거는 미확인이라고 적는다. 표가 길면 아래 표라고 적고 같은 절 안에 표를 둔다 |
| 조건과 한계 | 성립 조건과 보장하지 못하는 것. 상세는 요청받았을 때 늘리되 결정에 영향을 주는 조건과 한계는 생략하지 않는다 |
| 상태 | 방향 승인 여부, 검증(실제로 확인한 것), 미확인 사항 셋을 다 적는다 |

칸 이름은 조건과 한계다. 두 낱말을 가운뎃점으로 잇지 않는다. 가운뎃점은 금지 기호라 검사에 걸린다(W3).

규칙 다섯.

| 규칙 | 왜 |
|---|---|
| 한 턴에 결정 쟁점 하나 | 둘을 한 번에 물으면 답이 섞이고 어느 답이 어느 결정인지 기록이 못 가른다 |
| 기존 기준을 따르는 부분은 준수라고 표시만 한다 | 읽을 것은 벗어나는 부분과 새로 정할 부분이다 |
| 위치 표기는 근거 칸과 표에만 둔다. 산문에는 넣지 않는다 | R3. 산문에 절 번호와 경로가 박히면 쉬운 말이 아니다 |
| 결론을 좌우하는 개념을 사용자가 모르면 그 자리에서 짧게 풀고, 이해가 확인될 때까지 그 결정은 미확정으로 둔다 | 이해 못 한 개념이 쌓이면 승인 기준이 흐려진다 |
| 조건과 한계는 짧게 쓰더라도 생략하지 않는다 | 방향이 승인됐다고 검증된 것이 아니다. 무엇을 보장 못 하는지가 빠지면 승인이 검증으로 읽힌다 |

## 4. 게이트 (2026-09-14 S 검사 여섯)

    node harness/tools/check.mjs answer <답변파일> [--grade A|B|C|S]

| 검사 ID | 무엇 | 적용 등급 |
|---|---|---|
| answer.grade | 등급 판정. --grade가 없으면 자동 | 전부 |
| answer.lead | 첫 줄이 문장인가. 표와 제목은 실패 | A, B, S |
| answer.result-section | 마지막 절 제목이 결과인가 | A, B |
| answer.result-rows | 결과 절에 다섯 행이 다 있는가 | A, B |
| answer.result-empty | 앞의 셋이 해당 없음일 때 이유가 붙었는가 | A, B |
| answer.approval-one | 승인 요청 절이 정확히 하나인가. 없거나 둘 이상이면 실패 | S |
| answer.approval-rows | 그 절 표에 여섯 행이 다 있는가 | S |
| answer.approval-relation | 기존 기준과의 관계 칸이 준수, 변경, 신규 중 하나로 시작하는가 | S |
| answer.approval-status | 상태 칸에 방향 승인, 검증, 미확인 셋이 다 있는가 | S |
| answer.approval-evidence | 그 절 안에 위치 표기(경로:줄 또는 n절)가 하나 이상 있거나 미확인이 적혀 있는가 | S |
| answer.approval-no-result | 결과 절이 없는가. 대체이지 병기가 아니다 | S |
| answer.no-emdash, answer.no-middot, answer.no-bold | 줄표와 가운뎃점과 제목 밖 볼드 | 전부 |

자동 등급 판정은 위에서부터 처음 맞는 행을 쓴다. S 판정이 경로 판정보다 앞이다. 근거 칸에 경로가 들어가기 때문이다.

| 조건 | 등급 |
|---|---|
| 답변에 승인 요청으로 시작하는 절 제목이 있다 | S |
| 답변이 파일 경로를 쓴 적이 있다 | A |
| 답변에 Thought 또는 Observation 절이 있다 | B |
| 그 외이고 글자 수가 임계 미만 | C |
| 그 외 | B |

임계값은 1200자다. 실측 표본이 없어 정한 첫 판이고, 오탐이 나오면 harness/state/troubleshooting.md에 적어 조정한다.
