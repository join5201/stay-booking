# harness/tasks/

무엇이 들어가는가: 작업 계약이다. 한 Task가 무엇을 입력으로 받고 무엇을 바꿔도 되며 무엇으로 완료를 판정하는지 적은 문서.

왜 필요한가: 계약이 없으면 평가자에게 넘길 파일 목록을 정할 수 없다. 허용 입력이 계약에만 있기 때문이다(HR1).

파일명 규약 (2026-09-08 갱신)

| 종류 | 규약 | 예 |
|---|---|---|
| 문서 Task | task-S{Step}.md | task-S8.md |
| 기능별 개발 Task | task-S{Step}-{기능키}.md | task-S9-catalog.md |

개발 Task에 기능키를 붙이는 이유는 Step 9가 한 덩어리가 아니기 때문이다. 기능 하나마다 백엔드와 테스트, 프론트, 연결 테스트, 검증까지 세로로 내려가고(N9) 그 한 벌이 계약 하나다. Step 번호만 쓰면 계약 하나가 기능 여럿을 덮어 변경 허용 범위를 정할 수 없다.

기능키는 10-6 기능별 API와 검증 연결 표의 구현 묶음 이름을 쓴다. catalog, inventory, promotion, booking, payment, cancel 여섯이다.

승인 기록을 문서 안에 남긴다. 계약을 승인하기 전에는 생성 단계로 넘어가지 않는다.
