# 트러블슈팅 기록 (harness/state/troubleshooting.md)

최초 작성: 2026-09-07
최종 갱신: 2026-09-07 (H2 원본 정렬. 1행 추가)

왜 이 파일이 필요한가: 같은 실패를 두 번 디버깅하는 것을 막는다. 실패가 대화에만 남으면 세션이 끝날 때 사라지고, 다음 세션이 같은 벽에 다시 부딪힌다.

무엇을 적는가: 하네스를 돌리다 막힌 것 전부다. 검사 스크립트 오류, 승인 프롬프트, 평가자가 지시를 벗어난 경우, 앱 중단, 형식 보정 실패. 해결하지 못한 것도 미해결로 적는다. 적지 않으면 두 번째인지 알 수 없다.

행 형식: 임시다. 날짜시각, 단계 또는 Task, 증상, 원인, 조치, 상태 여섯 칸이다. 정식 형식은 H5에서 progress.md 정식 형식과 같이 확정한다.

규칙 세 개.
1. 추가 전용이다. 기존 행을 고치지 않는다. 상태가 바뀌면 새 행을 추가한다.
2. 같은 원인이 두 번째로 나오면 harness/state/knowledge.md에 승격하고, 이 표의 상태 칸에 승격을 적는다. 승격된 항목은 07 v3의 DO NOT 블록에 한 줄로 올라간다(harness/docs/10-8 5-7).
3. 이 파일은 평가 입력이 아니다. 평가자에게 넘기지 않는다(harness/docs/10-4 4절, harness/prompts/evaluate.md 3항).
