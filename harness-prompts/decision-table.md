## 지적별 결정

원본의 모든 지적을 한 행씩 옮긴다. 아래 표는 인계용 양식이며 실제 평가 규칙의 원래 출력 스키마를 검증했다는 뜻은 아니다. 원본에 있는 추가 필드도 보존한다.

| 리포트 A/B | 원본 번호 | 지적 ID | 심각도 | 대상 위치 | 위반 기준 | 원문 지적 | 원문 근거 | 결정 | 이유 |
|---|---|---|---|---|---|---|---|---|---|

원문 지적이나 근거가 여러 줄이면 별도 인용 블록으로 보존하고 해당 지적 ID와 연결한다. 내용을 요약하거나 삭제하여 원문과 달라지게 하지 않는다.

사용자가 바꾸는 열은 결정과 이유뿐이다. 원본 번호, 지적 ID, 심각도, 위치, 위반 기준, 지적 내용, 근거는 바꾸지 않는다. 오판 정정도 원본 심각도를 고치는 방식으로 처리하지 않는다.

| 결정 값 | 사용 조건 |
|---|---|
| 수용 | 반영 대상으로 정한다 |
| 거부 | 반영하지 않는 이유를 반드시 남긴다. 치명 오판 정정은 아래 판단 기록과 연결한다 |
| 반박 | 원본 심각도가 확인필요일 때만 사용한다. 확인한 근거와 판단을 이유에 적는다 |

치명과 보통에는 반박을 사용할 수 없다. 치명에 거부를 적었다는 사실만으로 해당 지적이 해결되거나 오판으로 정정된 것은 아니다. 실제 결함을 인정하면서 감수하는 결정은 오판 정정으로 처리하지 않는다.

## 반영 전 G2 확인

이 항목은 확인 절차다. 앱이 자동으로 검사했다고 가정하지 않는다. 확인자와 확인 결과를 남긴다.

- [ ] 평가 대상, 계약, A/B 리포트의 버전이 결정표와 일치한다.
- [ ] A와 B 원본의 지적 ID 집합과 결정표의 지적 ID 집합이 같다. 누락, 추가, 중복이 없다.
- [ ] 원본의 각 행과 결정표를 대조했고, 결정과 이유 외의 정보가 동일하다.
- [ ] 전체 행 수가 A와 B 원본 지적 수의 합과 같다. 지적 수가 0이면 리포트가 실제로 정상 완료되었는지 확인했고 파싱 실패나 평가 미완료를 0건으로 취급하지 않았다.
- [ ] 모든 행의 결정이 수용, 거부, 반박 중 하나다. 빈 결정이 없다.
- [ ] 모든 거부에 이유가 있고, 반박은 원본 심각도가 확인필요인 행에만 있다.
- [ ] 치명 오판 정정을 주장한 행마다 근거, 대안, 안티패턴, 사용자 결정, 날짜가 원본 지적에 연결되어 있다.

| 확인 항목 | 기록 |
|---|---|
| 확인자와 날짜 | {{필수}} |
| G2 결과 | {{통과 또는 미완료}} |
| 미완료 사유 | {{해당하면 작성}} |

하나라도 확인하지 못하면 반영 준비 미완료로 기록한다. 모델이 원본 행의 심각도를 낮추거나 행을 제거하여 이 검사를 통과시키면 안 된다.

## 반영과 최종 확인 인계

결정표 작성 완료, 오판 정정 완료, 최종 반영본 검증 완료는 서로 다른 상태다. 수용 항목의 반영과 미수용 항목의 무변경을 diff로 확인한다. 재평가는 R2까지이며 횟수 소진은 완료 근거가 아니다.

| 확인 대상 | 기록 |
|---|---|
| 반영본 절대경로와 버전 또는 해시 | {{반영 후 작성}} |
| 수용 항목 반영 확인 | {{지적 ID별 확인 위치 또는 검증 기록}} |
| 미수용 항목 무변경 확인 | {{diff 확인 기록}} |
| 남은 실제 치명 지적 | {{지적 ID 또는 없음}} |
| 오판 정정 완료 항목 | {{지적 ID와 판단 기록 위치 또는 없음}} |
| 마지막 반영본에 필요한 검증과 결과 | {{검증별 결과와 기록 위치}} |
| 코드 작업의 직접 실행 근거 | {{실행 명령, 환경, 종료 상태와 로그 또는 해당 없음}} |
| 평가 대상 소스와 테스트의 무변경 확인 | {{평가 전후 버전 대조 또는 해당 없음}} |
| 검증 미완료 사항 | {{미완료 사항 또는 없음}} |
| 사용자 최종 완료 판단과 날짜 | {{완료 또는 미완료, 이유, 날짜}} |
| 실제 판단 및 확인에 사용한 시간 | {{실측값 또는 미측정}} |

실제 치명이 남아 있거나 마지막 반영본에 필요한 검증이 남아 있으면 미완료로 기록한다. 평가자나 반영자가 사용자 대신 done을 확정하지 않는다.
