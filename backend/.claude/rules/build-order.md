## 4. 만드는 순서

묶음 하나는 아래에서 위로 올라간다. 계약 8절의 단계 번호와 같다.

| 단계 | 층 | 왜 이 순서인가 |
|---|---|---|
| 4 | domain, application, infrastructure | 규칙이 먼저다. API 모양이 규칙을 바꾸면 안 된다 |
| 5 | 테스트 | 규칙이 지켜지는지를 API 없이 본다 |
| 6과 6-2 | api | 규칙이 선 뒤에 입구를 붙인다 |
| 9 | 검증 표 | 문서의 검증 항목과 실제 테스트를 줄 맞춘다 |

한 턴에 한 단계다. 각 단계 끝에서 멈추고 사용자 확인을 받는다.
