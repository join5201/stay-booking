## 3. 층

컨텍스트 하나 안에 층이 넷이다. 근거는 `document/06-4` 1-4 검증 책임 위치 표다.

| 층 | 하는 일 | 안 하는 일 |
|---|---|---|
| api | HTTP를 도메인 말로 바꾼다. 형식을 본다 | 규칙 판단, 저장소 직접 호출 |
| application | 트랜잭션 경계. 컨텍스트를 넘는 선행조건. 이벤트 발행 | 불변식 재검사, 형식 검사 |
| domain | 불변식을 지킨다. 상태를 바꾸는 유일한 입구 | HTTP와 스프링 데이터를 모른다 |
| infrastructure | 저장, 조회, 잠금. 유일성과 무결성 | 규칙 판단 |

의존은 한 방향이다. api가 application을, application이 domain을 부른다. infrastructure는 domain이 선언한 인터페이스를 구현한다. domain은 아무도 안 가리킨다.

같은 검사를 여러 층에 두는 것은 중복이 아니다. 보는 것이 다르다.

| 층 | 요금 하한 1을 보는 방식 |
|---|---|
| api | 요청 값의 형태. `@Min(1)` |
| domain | 불변식 I2. `InvalidRateException` |
| DB | 해당 없음. DB는 유일성만 본다 |

층을 지울 때 무엇이 깨지는지로 판단한다. api를 지우면 오류 응답이 뭉개지고, domain을 지우면 다른 입구가 생길 때 뚫리고, DB를 지우면 동시 요청이 둘 다 통과한다.

### 3-1. 리포지토리를 두 파일로 두는 이유

`infrastructure`에 파일이 둘씩 있다.

| 파일 | 역할 |
|---|---|
| `{이름}JpaRepository` | 스프링 데이터 인터페이스 |
| `Jpa{이름}Repository` | 어댑터. 도메인 인터페이스를 구현하고 위를 부른다 |

합치면 domain 인터페이스가 스프링 데이터를 상속하게 되고 그 순간 domain이 프레임워크를 참조한다. 코드 평가 기준의 레이어 역전에 걸린다.

### 3-2. shared에 올리는 기준

두 번째 컨텍스트가 쓰기 시작하면 올린다. 하나만 쓰는 것을 미리 올리지 않는다. 근거는 `document/06-1` 4절이다. `Clock` 빈이 이 기준으로 catalog에서 shared로 옮겨졌다(2026-09-09).

### 3-3. 이벤트는 구독 쪽이 커밋 뒤를 지킨다 (2026-09-11 신설)

`document/06-2` 94행은 이벤트 발행을 커밋 후로 적는다. 앱 서비스는 `@Transactional` 안에서 `publishEvent`를 부르고 그 자리는 바꾸지 않는다. 발행을 커밋 뒤로 옮기면 롤백된 요청이 이벤트를 내지 않는지를 보는 이벤트 테스트가 전부 깨진다. 대신 구독자가 지킨다.

| 번호 | 규칙 |
|---|---|
| E1 | 구독자는 `@TransactionalEventListener`로 건다. 기본 phase가 AFTER_COMMIT이라 커밋된 사실만 받는다. `@EventListener`로 걸지 않는다 |
| E2 | 첫 구독자가 생기는 묶음은 롤백된 요청의 이벤트를 구독자가 받지 않는 테스트를 8-1에 필수로 올린다 |

지금은 구독자가 없어 겉으로 드러나지 않는다. task-S9-inventory-rate R1 평가 B-03이 이 어긋남을 짚었고 결정표가 코드 대신 이 규칙으로 닫았다.
