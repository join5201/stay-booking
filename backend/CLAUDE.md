# CLAUDE.md (backend 규칙)

최초 작성: 2026-09-10
최종 갱신: 2026-09-11 (3-3절 이벤트 구독 규칙 신설. R1 평가 B-03)
독자: backend/ 아래에서 일하는 Claude Code와 코딩 에이전트

왜 이 파일이 필요한가: 루트 CLAUDE.md는 하네스 규칙이라 백엔드 코드를 어디부터 읽어야 하는지, 층마다 무엇을 하는지, 지금 어느 단계인지를 적지 않는다. 그래서 세션마다 사람이 그것을 말로 설명하게 된다. 이 파일이 그 설명을 대신한다.

루트 CLAUDE.md는 그대로 적용된다. 이 파일은 그것을 덮지 않고 backend 몫만 더한다. 충돌하면 루트가 우선이다.

## 1. 시작할 때 읽는 순서

세 파일이면 지금 무엇을 하는지가 잡힌다. 이 순서로 읽는다.

| 순서 | 파일 | 무엇을 얻나 |
|---|---|---|
| 1 | `../harness/tasks/task-S9-{기능키}.md` | 지금 묶음의 범위, 단계 표(8절), 테스트 목록(8-1절) |
| 2 | `../harness/state/progress.md`의 그 Task 마지막 행 | 어디까지 했고 다음이 무엇인지 |
| 3 | `../document/11-o2o-api-spec.md`의 해당 API 절 | 경로, 필드, 상태 코드, 오류 코드 |

기능키가 무엇인지는 `../harness/docs/10-6` 3절 기능별 API와 검증 연결 표의 행 이름이다. 진행 중인 계약은 `harness/tasks/`에서 가장 최근 것이다.

파일이 여럿이면 마지막 행이 아니라 그 Task의 마지막 행을 읽는다. progress.md는 세션 여럿이 같이 쓰고 순서가 보장되지 않는다.

## 3. 층

컨텍스트 하나 안에 층이 넷이다. 근거는 `../document/06-4` 1-4 검증 책임 위치 표다.

| 층 | 하는 일 | 안 하는 일 |
|---|---|---|
| api | HTTP를 도메인 말로 바꾼다. 형식을 본다 | 규칙 판단, 저장소 직접 호출 |
| application | 트랜잭션 경계. 컨텍스트를 넘는 선행조건. 이벤트 발행 | 불변식 재검사, 형식 검사 |
| domain | 불변식을 지킨다. 상태를 바꾸는 유일한 입구 | HTTP와 스프링 데이터를 모른다 |
| infrastructure | 저장, 조회, 잠금. 유일성과 무결성 | 규칙 판단 |

의존은 한 방향이다. api가 application을, application이 domain을 부른다. infrastructure는 domain이 선언한 인터페이스를 구현한다. domain은 아무도 안 가리킨다.

같은 검사를 여러 층에 두는 것은 중복이 아니다. 보는 것이 다르다.

| 층 | 요금 하한 1을 보는 방식 |
|---|---|
| api | 요청 값의 형태. `@Min(1)` |
| domain | 불변식 I2. `InvalidRateException` |
| DB | 해당 없음. DB는 유일성만 본다 |

층을 지울 때 무엇이 깨지는지로 판단한다. api를 지우면 오류 응답이 뭉개지고, domain을 지우면 다른 입구가 생길 때 뚫리고, DB를 지우면 동시 요청이 둘 다 통과한다.

### 3-1. 리포지토리를 두 파일로 두는 이유

`infrastructure`에 파일이 둘씩 있다.

| 파일 | 역할 |
|---|---|
| `{이름}JpaRepository` | 스프링 데이터 인터페이스 |
| `Jpa{이름}Repository` | 어댑터. 도메인 인터페이스를 구현하고 위를 부른다 |

합치면 domain 인터페이스가 스프링 데이터를 상속하게 되고 그 순간 domain이 프레임워크를 참조한다. 코드 평가 기준의 레이어 역전에 걸린다.

### 3-2. shared에 올리는 기준

두 번째 컨텍스트가 쓰기 시작하면 올린다. 하나만 쓰는 것을 미리 올리지 않는다. 근거는 `../document/06-1` 4절이다. `Clock` 빈이 이 기준으로 catalog에서 shared로 옮겨졌다(2026-09-09).

### 3-3. 이벤트는 구독 쪽이 커밋 뒤를 지킨다 (2026-09-11 신설)

`../document/06-2` 94행은 이벤트 발행을 커밋 후로 적는다. 앱 서비스는 `@Transactional` 안에서 `publishEvent`를 부르고 그 자리는 바꾸지 않는다. 발행을 커밋 뒤로 옮기면 롤백된 요청이 이벤트를 내지 않는지를 보는 이벤트 테스트가 전부 깨진다. 대신 구독자가 지킨다.

| 번호 | 규칙 |
|---|---|
| E1 | 구독자는 `@TransactionalEventListener`로 건다. 기본 phase가 AFTER_COMMIT이라 커밋된 사실만 받는다. `@EventListener`로 걸지 않는다 |
| E2 | 첫 구독자가 생기는 묶음은 롤백된 요청의 이벤트를 구독자가 받지 않는 테스트를 8-1에 필수로 올린다 |

지금은 구독자가 없어 겉으로 드러나지 않는다. task-S9-inventory-rate R1 평가 B-03이 이 어긋남을 짚었고 결정표가 코드 대신 이 규칙으로 닫았다.

## 4. 만드는 순서

묶음 하나는 아래에서 위로 올라간다. 계약 8절의 단계 번호와 같다.

| 단계 | 층 | 왜 이 순서인가 |
|---|---|---|
| 4 | domain, application, infrastructure | 규칙이 먼저다. API 모양이 규칙을 바꾸면 안 된다 |
| 5 | 테스트 | 규칙이 지켜지는지를 API 없이 본다 |

한 턴에 한 단계다. 각 단계 끝에서 멈추고 사용자 확인을 받는다.

## 5. 테스트 규칙

| 번호 | 규칙 |
|---|---|
| T1 | 실패 케이스와 통과 케이스를 짝으로 붙인다. 금지만 검사하면 허용 값까지 막는 가드도 초록이다 |
| T2 | 경계는 양쪽을 본다. 366일 거절이면 366일 통과도 본다 |
| T3 | 유일성과 롤백과 잠금은 실제 MySQL에서 본다. 메모리 저장소로 바꾸면 확인하려던 것이 사라진다 |
| T4 | 날짜를 상수로 박지 않는다. 오늘에서 센다. 박으면 그 날이 지날 때 다른 것을 검사한다 |
| T5 | 시각이 결과를 바꾸는 테스트는 `Clock`을 고정해 끼운다. 서버를 띄우는 테스트는 상대 날짜를 쓴다 |
| T6 | 이번 묶음에 만들 수 없는 상태는 DB에 직접 놓는다. 없는 경로를 만드는 것이 아니라 다음 묶음이 만들 상태를 미리 놓는 것이다. 왜 그런지를 테스트 주석에 적는다 |

T6의 실제 예가 `InventoryApiTest`의 판매분 seeding이다. 판매 수를 올리는 행동이 예약 묶음에 있어서 이번 묶음 코드로는 그 상태를 만들 수 없다.

## 6. 명령

`JAVA_HOME`을 21로 준다. PATH의 java는 17이다.

| 하는 일 | 명령 |
|---|---|
| DB 올리기 | `docker compose -f backend/docker-compose.yml up -d` |
| 테스트 | `JAVA_HOME=<JDK 21> ./backend/gradlew.bat -p backend test` |
| 컴파일만 | `JAVA_HOME=<JDK 21> ./backend/gradlew.bat -p backend compileJava` |
| 서버 띄우기 | `JAVA_HOME=<JDK 21> ./backend/gradlew.bat -p backend bootRun` |
| 게이트 | `node harness/tools/check.mjs g1 <소스> --type code --artifact <junit.xml>` |

PowerShell에서는 `&&`가 안 된다. `;` 로 잇거나 `; if ($?) { }` 를 쓴다.

Docker Desktop이 꺼져 있으면 `docker desktop start`로 켠다. 엔진이 올라오는 데 몇 분 걸린다. 나머지 실패 예시는 README.md 3절에 있다.

테스트 결과 사본은 `../harness/out/task-S9-{기능키}-R1/step{단계}/`에 둔다. 실제 서버에 친 기록은 같은 폴더의 `http-calls.txt`다.

## 7. 개발용 인증

배포가 범위 밖이라 실제 인증이 없다. 헤더로 행위자를 정한다.

| 헤더 | 값 예시 |
|---|---|
| X-Dev-Actor-Id | host_001, host_002, guest_001, operator_001, mock_001 |

`host_002`가 있는 이유는 소유권 검사에 소유자가 둘 필요해서다. 남의 자원은 403이 아니라 404다. 403은 자원의 존재를 알려 준다.

## 8. DO NOT

| 번호 | 금지 | 깨지는 것 |
|---|---|---|
| BN1 | 명세에 없는 응답 필드 더하기 | API 계약 준수 축. 테스트가 필드 수를 센다 |

| BN4 | 통합 테스트를 메모리 저장소로 바꾸기 | 유일성과 롤백과 잠금이 확인되지 않는다 |
