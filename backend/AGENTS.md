# AGENTS.md (backend 평가자 규칙)

최초 작성: 2026-09-10
최종 갱신: 2026-09-10 (신설)
독자: backend/ 아래 코드를 평가하는 코딩 에이전트. 실제 운용에서는 Codex의 새 작업이다.

왜 이 파일이 필요한가: 루트 AGENTS.md는 문서 평가를 기준으로 쓰였다. 코드 평가에서만 생기는 것이 있다. 무엇을 읽어야 하고 무엇을 읽으면 안 되는지, 결과 파일을 어디까지 믿을지, 어느 명령까지 돌려도 되는지다.

Codex는 Git 루트에서 현재 디렉터리까지 내려오며 AGENTS.md를 모은다. 아래 파일이 뒤에 와서 우선한다. 그러므로 이 파일은 루트 AGENTS.md를 덮지 않고 더한다. E1부터 E8은 그대로 걸린다.

Claude Code는 이 파일을 읽지 않는다. 생성자 규칙은 같은 폴더의 CLAUDE.md다.

## 1. 읽는 것과 읽지 않는 것

허용 입력은 그 라운드 작업 계약의 허용 입력 칸이 정한다. 목록에 없으면 읽지 않는다(E6).

| 읽는다 | 읽지 않는다 |
|---|---|
| 계약 5절이 적은 평가 대상 코드 | `../harness/docs/` 전체 |
| `../document/11-o2o-api-spec.md`의 해당 API 절 | `../harness/state/` 아래 기록 |
| `../document/06-2`와 `06-4`의 해당 절 | 이전 라운드 리포트, 결정표 |
| 계약이 적은 결과 파일 경로 | 생성 대화 |

`harness/state/progress.md`를 읽지 않는 이유는 그 파일에 생성자의 판단과 다음 계획이 적혀 있기 때문이다. 그것을 보면 블라인드가 아니다.

## 2. 코드 평가에서만 걸리는 제약

| 번호 | 규칙 |
|---|---|
| BE1 | 결과 파일을 그대로 믿지 않는다. 계약 9절의 명령을 직접 돌려 대조한다. 돌리지 못했으면 돌리지 못했다고 적는다 |
| BE2 | 테스트가 통과했다는 사실과 그 테스트가 무엇을 지키는지는 다르다. 둘을 따로 적는다 |
| BE3 | 실패 케이스만 있는 검사는 지적 대상이다. 허용 값까지 막는 가드도 그 검사에서는 초록이다 |
| BE4 | 명세와 코드가 다르면 명세가 정본이다. 명세가 비어 있으면 추측하지 말고 확인필요로 남긴다 |
| BE5 | 층 위반은 파일이 놓인 위치가 아니라 import로 판정한다. domain이 스프링 데이터나 웹 타입을 참조하는지를 본다 |
| BE6 | 커버리지 숫자를 등급 근거로 쓰지 않는다. 계약 8-1절의 항목마다 대응 테스트가 있는지를 본다 |

## 3. 돌려도 되는 명령

계약 9절이 승인 명령으로 적은 것만 돌린다(E2). 이번 계열에서는 셋이다.

| 명령 | 무엇 |
|---|---|
| `docker compose -f backend/docker-compose.yml up -d` | 테스트 DB |
| `JAVA_HOME=<JDK 21> ./backend/gradlew.bat -p backend test` | 테스트 |
| `node harness/tools/check.mjs g1 <소스> --type code --artifact <junit.xml>` | 게이트 |

바꿔도 되는 것은 빌드 산출물과 로그와 테스트 DB뿐이다(E3). 테스트 DB는 `o2o_catalog_test`이고 `ddl-auto`가 `create-drop`이라 스키마가 매번 지워진다. 그 범위를 벗어나지 않는다.

`bootRun`은 목록에 없다. 서버를 띄우는 것은 생성자 몫이고 그 결과는 `http-calls.txt`로 온다.

## 4. 층과 근거 문서

지적을 적을 때 어느 층의 문제인지와 어느 절을 어겼는지를 같이 적는다.

| 층 | 근거 절 |
|---|---|
| api | 11 해당 API의 필드표와 오류 표, 06-4 1-4의 컨트롤러 행 |
| application | 06-4 1-2 계약표, 06-4 1-4의 앱 서비스 행 |
| domain | 06-2 애그리거트, 06-4 1-1 불변식 카탈로그 |
| infrastructure | 06-4 1-4의 DB 행, 06-4 0절 락 선언 |

## 5. 미결

코드 평가 기준(`../harness/prompts/eval-criteria-code.md`)의 판이 확정이 아니다. 축과 등급은 그 파일을 따르고 이 파일에 옮겨 적지 않는다. 두 곳에 두면 갈라진다.
